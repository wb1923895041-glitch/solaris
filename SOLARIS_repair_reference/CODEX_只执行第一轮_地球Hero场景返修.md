你是一名高级 Three.js 渲染、数字天文馆视觉以及天体科学可视化工程师。当前 SOLARIS 第0期/第1期验收材料已经提交。先阅读 `SOLARIS_第0-1期_独立审查报告.md`、真实截图和同屏对照图，结合**你当前最新的本地仓库**逐项核实。

## 强制边界
1. 禁止新建项目或覆盖旧代码；先 `git status`，确保恢复点可用。不得更改科学底座的 UTC/TDB、JPL `.f64` 数据、查询来源、误差检测、物理单位、天体实际坐标及时间控制规则。
2. 禁止用参考图作为场景背景、贴图或真实位置；禁止强行把八行星排成一排，禁止强行把土星/木星挪近镜头构图。
3. 只面向 Windows PC 桌面 1920×1080 / 2560×1440 / 3840×2160，优先 1440p。无需手机适配。
4. **先执行 A 阶段，停止等待验收。** 这是单场景视觉竖切，而不是一次“做完全部”。

## 阶段 A（当前只做这个）：地球探索 Hero Scene

### A0 盘点与回归
- 跑已有 `npm run build`、`npm run check:contracts`、`npm run check:science`；记录真实输出。
- 检查 `src/render/scene.ts`、`src/render/textures.ts`、`src/style.css`、`src/main.ts`，指出与报告中 V01–V07 对应的具体代码。
- 以当前截图为改造前基线。记录尺寸、浏览器和所有图形选项。

### A1 行星材质
- 将地球从一个单层 Blue Marble 球体升级为独立模块（EarthVisual/EarthAtmosphere/EarthClouds 等）。高分辨率贴图使用可核验的 NASA/USGS 资源，允许在合法条件下预处理，不许使用生成式海报做球面贴图。
- 按正确色彩空间、法线、粗糙度和太阳光照处理；云层独立；海洋镜面反射避免塑料质感；大气薄且物理上方向一致；避免大面积 Bloom 和强蓝边。
- 如果没有可核验的实时云层或地球姿态，明确写明静态/教学可视化属性。不能把固定的地理日夜图冒充某日期真实日夜分布。

### A2 沉浸式镜头
- 改善从总览到地球的转场，修复“聚焦后所有其他天体与轨迹都被隐藏”的机制。可用按距离/像素阈值渐隐与局部层级，**但只改变呈现，不改变物理位置**。
- 支持鼠标拖动环绕、滚轮平滑缩放、Esc返回。转场可以打断、不会镜头穿球、不会将太阳方向判反。
- 三维地球必须在不同角度都真实，不准用单张地球大图当背景。

### A3 UI 提升
- 地球 Hero 画面比例合理，侧栏信息不抢主体；标注具有优先级，信息可读，禁止8px作为主体正文。
- 仅做桌面端设计，避免小字、窄面板、透明玻璃大面积堆叠；不额外开发百科、卫星、N体或其他页面。

### A4 验收
输出：
1. 2560×1440 原始运行截图：地球全貌、地球局部近景、旋转后、明暗交界、数据侧栏；另附一张改造前后同屏对照。
2. 30秒以上实际交互录屏，包括总览→地球→环绕→放大→日期跳转→返回；如果视频尺寸较小，用1440p原图补充。
3. 帧时间 P50/P95、GPU内存与渲染调用次数（可获取项），明确区分 rAF与真实屏幕呈现。
4. 科学数据未变化的自动化测试与错误报告；无通过证据不得写“通过”。
5. 哪些画面属于真实数据，哪些为增强可视化，以可读文字告知用户。

**A阶段验收完成后立即停止。不得提前处理太阳、其他行星或整个总览。**
