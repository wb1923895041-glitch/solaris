# SOLARIS 第 0–1 期独立审查与返修报告

审查对象：用户上传的 `SOLARIS_第0期_验收包.zip`、`SOLARIS_第1期_验收包.zip`。本报告基于包内源码、文档、数据、运行截图、日志，以及单独运行的 Python 数据复算。**没有声称连接到用户的本地 Codex 工作区或重新在 Windows 独立显卡上运行浏览器。**

## 总结：技术底座留用，视觉验收不通过

- **第 0 期：工程基座/文档验收可接受。** 其范围明确是空场景、科学契约和来源规划；空画面不是缺陷，但不能当成任何视觉终稿。
- **第 1 期：科学星历与数据工程可条件验收；视觉/产品体验不通过。** 不建议重做历表、时标和单位转换；应冻结科学层，返修渲染、相机、信息组织和质量门槛。
- **未来分期 2–8 应停止推进**，直到一个实机 1440p 总览 + 一个地球特写达到重新确认的视觉门槛。

## 科学数据独立复算

将 `data/phase-1/manifest.json` 与 `public/data/*.f64` 一一对照并计算 SHA-256：**9/9 一致**。使用 `data/phase-1/validation.json` 的9组×48个留出状态，独立在 Python 中实现三次 Hermite 插值：

- 样本数：**432**；太阳及八行星均覆盖。
- 最大三维位置差：**0.064723 km**，发生在水星。
- 最大三维速度差：**9.60185×10⁻⁶ km/s**，发生在水星。
- 其他8组均在报告的容差内，和验收包自身汇总一致。

结论：**本地数据完整性与离线插值实现是有证据支持的**。局限：对照使用验收包内保存的 JPL 结果，属于同源交叉抽样；未实时重新查询 NASA，也未独立观测验证，不等于未来所有年份、所有天体姿态或 N 体精度的保证。

## 验收建议（不要进入第2期的其余天体）

### 补救 A：科学与工程冻结

先做 `npm run build`、`npm run check:contracts`、`npm run check:science` 的本地复跑，保存环境、日志，确保修改渲染后科学数据与测试逐位不变。先建立 Git commit/恢复点，不能仅记录某个 tree hash 就宣称可正常回滚。

### 补救 B：单场景竖切

先只做 **地球特写** 一个场景：高清可溯源地球纹理/云层/薄大气、太阳方向的真实晨昏线、近距离细节、平滑逼近相机、清晰的数据面板；和原截图并排验收。不引入月球、航天器、N 体或新玩法。**地球合格才扩展太阳与全局总览**。

### 补救 C：总览电影级表达

不更改行星真实位置。重新设计场景构图、星空、太阳、曝光、摄影视角、轨道线层级、UI主次关系，提供一套最终全屏运行截图与视频。概念图不必在某日期“同框横排”，那是物理矛盾；基准约束的是质感、层次和信息架构。

### 必须满足的门槛

- 1440p 实际浏览器截图，无借助拼贴、静态背景假扮3D。
- 太阳/地球能独立近景清晰呈现；地球聚焦保留空间参考。
- 日夜分界方向与同一时刻太阳位置一致；所用姿态/云层的真实或示意状态说明清晰。
- 无量纲/真实比例标签准确，科学计算输出与阶段一基线一致。
- 手动测试至少：总览→聚焦地球→旋转→放大→切日期→返回，录制持续运行视频。
- 1440p 实际桌面窗口测量帧时间，而非仅使用无头 rAF 结果。
- 每项通过/不通过必须有截图、测试日志或说明，不能只填“完成”。

## 推荐取舍

第 0 期可保留，第一期科学/数据部分**条件通过**，第一期视觉与体验**必须返修**。暂停所有后续期；完成地球“英雄场景”与太阳系总览两个视觉门槛后再决定是否继续其他卫星、小行星带与教学模块。
