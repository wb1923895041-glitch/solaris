# 浏览器、视觉与性能验收

2026-10-29。以本地生产构建（4173）进行真实Chrome/Edge浏览器验收，原始stdout、控制台和截图保存在output/playwright/phase-1。浏览器为无头模式，硬件加速已验证。

## 实际结果

Chrome 32 项 / Edge 32 项全部通过；15项契约检查和14组科学行为检查通过。测试覆盖四个日期×九个目标、可复现跳转、暂停、零倍率、比例状态隔离、真实科学比例、相机拖动/缩放/聚焦/返回、搜索、来源面板、越界、刷新及三分辨率布局。

另在真实画布上通过数学投影定位太阳，验证单击选中/双击聚焦；Space/F/Esc、输入框快捷键隔离、全部资源本地化通过。损坏399.f64后的真实浏览器故障注入确认：完整性校验失败、0个Canvas、播放禁用，不生成替代轨道；恢复文件后正常启动。详见extra-interactions.txt、failure-test.txt。

正常Chrome/Edge控制台最终均0 errors / 0 warnings；故障会话单独记录。最终CSS修正1080p左栏阶段标记重叠和详情按钮裁切，Chrome/Edge最终布局复核均通过，见final-layout JSON与日志。最初datetime-local自动化输入中的零秒被浏览器规范化，改为符合原生控件格式后重跑通过。原CLI录屏返回空文件，已改用Playwright原生context.recordVideo重新录制并实际播放验证；空文件未作为最终证据。

## 复现

启动生产预览：`npm run preview -- --port 4173 --strictPort`，执行 `npm run qa:prepare`。然后使用Playwright CLI分别open Chrome/Edge、snapshot，再 `run-code --filename scripts/browser-phase1-qa.js` 或edge版本。连续播放性能脚本为browser-phase1-performance.js；画布快捷键为browser-phase1-extra.js；故障注入为browser-phase1-failure.js。

录屏使用 `node scripts/record-phase1.mjs`；它还需5173开发服务提供本地输出视频供播放核验。脚本保存文件后关闭录制上下文，再实际打开并播放视频，检查长度、解码与错误列表。原CLI空文件路径返回不计为成功。

- chrome: `Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) HeadlessChrome/155.0.0.0 Safari/537.36`；DPR 1。
- edge: `Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) HeadlessChrome/156.0.0.0 Safari/537.36 Edg/156.0.0.0`；DPR 1。
